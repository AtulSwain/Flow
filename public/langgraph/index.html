Agents are graphs.
LangGraph makes them durable.

LangGraph models an AI application as a stateful graph: nodes do work, edges decide what runs next, and a shared state is checkpointed after every step — so agents can loop, branch, pause for humans, recover from failure and travel back in time.

01 — Overview

What is LangGraph?

LangGraph is an open-source library (Python & JavaScript, MIT-licensed) from the LangChain team for building long-running, stateful agents and workflows. It is deliberately low-level: it doesn't hide your prompts or architecture behind magic — it gives you a runtime with the primitives agents need in production.

↻

Cycles, not just chains

Classic pipelines are DAGs. Agents loop: think → act → observe → think again. LangGraph supports cycles natively, with a recursion limit as a safety net.

◈

Durable execution

A checkpointer saves state after every super-step. Crash mid-run? Resume from the last checkpoint. Need a week-long approval? Pause and pick up later.

✋

Human-in-the-loop

interrupt() pauses a graph anywhere, surfaces data to a person, and resumes with their answer via Command(resume=…).

≋

First-class streaming

Stream full state, per-node updates, LLM tokens, or custom events — so users see progress while a multi-step agent works.

The mental model

  1. Define state — a typed schema (TypedDict, Pydantic, or Zod/Annotation in JS). Each key may have a reducer that says how updates merge.
  2. Add nodes — plain functions state → partial update. Call an LLM, a tool, an API, or anything else.
  3. Wire edges — fixed edges, conditional edges (routers), or dynamic Command / Send from inside a node.
  4. Compile — attach a checkpointer, store and interrupt points. You get a Runnable with invoke, stream, batch.
  5. Run on a thread — every invocation with the same thread_id continues the same persisted conversation.
graph.py
from langgraph.graph import StateGraph, START, END

builder = StateGraph(State)
builder.add_node("plan", plan)
builder.add_node("act", act)
builder.add_edge(START, "plan")
builder.add_conditional_edges("plan", route,
    {"act": "act", "done": END})
builder.add_edge("act", "plan")   # a cycle!

graph = builder.compile(checkpointer=saver)

03 — How it works

Inside the runtime: Pregel super-steps

Under the hood, a compiled graph is a Pregel program — an execution model inspired by Google's Pregel and the Bulk Synchronous Parallel (BSP) model. State lives in channels; nodes subscribe to channels and write to them. Execution proceeds in discrete super-steps.

1

Plan

Pick every node whose subscribed channels changed in the last step. On step 0 that's whatever follows START.

2

Execute

Run the selected nodes in parallel. Their writes are buffered — invisible to each other until the step ends.

3

Update

Apply buffered writes to channels via reducers, then save a checkpoint. Repeat until no node is triggered or END is reached.

      Channels & reducers

      Each state key is a channel. Without a reducer, a write overwrites (LastValue). With Annotated[list, add] or add_messages, writes are merged — that's how parallel branches safely append to the same list.

      Threads & checkpoints

      A thread is a sequence of checkpoints. get_state() reads the latest; get_state_history() lists them all. Invoke with an older checkpoint_id to replay or fork — that's time travel.

      Durability modes

      Choose how eagerly checkpoints are persisted: "exit" (only at the end — fastest), "async" (write while the next step runs), or "sync" (write before continuing — safest).

      06 — Models

      Bring any model

      LangGraph is model-agnostic — a node is just a function, so it can call any LLM or none at all. Through LangChain integrations, init_chat_model("provider:model") gives every provider the same interface for messages, tool calling, structured output and streaming.

      What a model must do well inside a graph

      Mix models per node

      Because each node owns its model call, you can route cost and capability precisely:

      • Planner / supervisor — your strongest reasoning model; it's called rarely but decides everything.
      • Workers / tool callers — a fast mid-tier model with reliable tool calling.
      • Classifiers / routers / graders — a small, cheap model with structured output.
      • Private data — a local open-weight model (e.g. via Ollama) for nodes that must not leave your network.
      • Fallbacks — model.with_fallbacks([...]) or a retry policy on the node to survive provider outages.

worker  = init_chat_model("anthropic:claude-sonnet-5-5")
grader  = init_chat_model("anthropic:claude-haiku-5-5")
local   = init_chat_model("ollama:llama3.1")
      07 — Ecosystem

      Where LangGraph sits

      LangGraph is the orchestration layer. Integrations come from below; observability and deployment come from above. Each layer is optional — LangGraph runs without LangChain or LangSmith.

      LangSmithTracing · Evals · Deployment · Studio
      Prebuilt agentscreate_agent · supervisor · swarm
      LangGraph runtimeStateGraph · Pregel · checkpoints · store
      IntegrationsChat models · tools · retrievers · vector stores
      LangSmith — trace every node, LLM call and tool call; run evaluations; deploy graphs as scalable APIs with task queues, cron and persistence (formerly “LangGraph Platform”). LangGraph Studio is its visual IDE for graphs.
      Prebuilt agents — high-level constructors built on LangGraph: LangChain's create_agent (successor to create_react_agent), plus langgraph-supervisor and langgraph-swarm for multi-agent setups.
      LangGraph — the graph APIs (StateGraph, Functional API with @entrypoint/@task), Pregel runtime, checkpointers (memory, SQLite, Postgres…) and the long-term memory Store.
      Integrations — provider packages (langchain-anthropic, langchain-openai…), tools, MCP adapters and retrievers. Use them — or call SDKs directly.
